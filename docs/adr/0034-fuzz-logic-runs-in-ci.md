# ADR 0034 — Fuzz logic runs in CI; the fuzzer only searches

## Date

2026-07-28

## Status

Accepted

## Context

`future_plan.md` Q0 asks for two things this repository had not done: extend the fuzz
harnesses to the parsers added since they were written (PEM label dispatch, PKCS#1,
SEC1, encrypted PKCS#8, the positional certificate walk, JWK Set selection, the JSON
JWE forms, claims duplicate rejection), and "retain reproducible regression fixtures".

The existing fuzz setup had a structural gap. `.github/workflows/fuzz.yml` is a
`workflow_dispatch` job that only *builds* the harnesses, on nightly, by hand. So the
body of a `fuzz_target!` — the part that decides which entry points get exercised and
what counts as a finding — is code that no pipeline compiles by default and nobody
runs on a schedule. New parsers shipped with no harness at all, and the README said,
accurately, "No seed corpus is checked in yet."

Two facts follow. Coverage-guided fuzzing from random bytes reaches shallow refusals
almost immediately and code behind structure almost never: it must *discover* that a
certificate is four nested sequences before it can reach the positional walk inside
one. And a crash discovered in a long run is only a regression if the input that
produced it can be re-executed next week, by something that runs on every commit.

## Decision

### Harnesses are added for the new parsers, with their budgets built in

Eight harnesses: `jwk_from_pem`, `jwk_from_der`, `certificate_extract`,
`encrypted_pkcs8`, `jwkset_select`, `jwe_json_flattened`, `jwe_json_general`,
`jwt_claims`. Two of them encode a policy rather than just calling a function:
`encrypted_pkcs8` runs at `PKCS8_MIN_ITERATIONS`, so a fuzz run measures parser
behaviour instead of PBKDF2 throughput and a regression that consults a file's own
iteration count before the budget becomes visible; `jwkset_select` uses the strict
policy plus one bounded sweep, because a caller choosing `Fallback::TryAll` is a
decision this crate must be able to refuse *without* being fuzzed into it.

### The corpus is generated by checked-in code and committed

`examples/fuzz_seeds.rs` writes `fuzz/seeds/<harness>/…`: real armor around real DER
(decoded out of `tests/fixtures/**`), real tokens built through the crate's own sign
and encrypt paths, documents with the specific malformations the policies exist for,
a JWK Set over the entry budget. `-- --check` regenerates and diffs, and the gate
fails when the committed corpus drifts.

Byte-stability is claimed only where it is true. Key-file, JWK, JWK Set, claims and
HMAC-token seeds are reproducible because they use fixed key material and fixed
payloads; the three `A256GCM` directories are compared by file name alone, because a
fresh random IV is what makes those documents secure and a byte-stable version would
require committing a fixed nonce. The exception is a constant in the generator
(`NON_DETERMINISTIC`), so a fourth non-deterministic directory is a deliberate edit
rather than a quiet hole in the drift check. Every key in the corpus is a literal in
the generator, so nothing committed is a secret.

### Every harness's sequence is mirrored in a test that runs on stable

`tests/fuzz_regressions.rs` reproduces each harness's call sequence as an ordinary
function and drives it over every seed plus deterministic mutations: every prefix, and
every single-byte flip for inputs short enough to enumerate (with sampled prefixes for
large ones, so a 300 KB "over the entry budget" seed does not turn the suite into a
batch job). This is not fuzzing — no search, no coverage feedback — but it *executes*
in CI, from the repository alone, on the stable toolchain CI uses.

### The mirrors are prevented from drifting, mechanically

- `fuzz_harness_entry_points_are_all_replayed` extracts every `jose_rs::…` call from
  `fuzz/fuzz_targets/*.rs` and requires this file to reference it too. Skipping
  requires an entry in `HARNESS_ONLY_ENTRY_POINTS` **with a written reason**, and an
  entry that stops being referenced by any harness fails the test, so the skip list
  cannot quietly grow or fossilize. It holds two PQ key generators, whose coverage
  lives in the post-quantum tests.
- `fuzz_targets_are_syntactically_well_formed` checks the `#![no_main]` + single
  `fuzz_target!` + delimiter balance + `[[bin]]` registration of every harness,
  because these files cannot be type-checked here.

### Not done

No scheduled fuzzing job, and no corpus from libFuzzer's own discoveries committed
automatically. Nightly fuzzing on a schedule is an infrastructure decision (runner
time, who is paged when it finds something) that this change does not make; what it
does make possible is dropping a crash artifact into `fuzz/seeds/` and having stable
CI own it from then on.

## Consequences

* New parsers get fuzz coverage **and** a stable-runnable regression for it; a crash
  found nightly becomes a permanent CI test by copying one file.
* Two copies of each input sequence now exist — harness and mirror — which is real
  duplication, paid for with a check that they cover the same API surface. A harness
  that gains a call the mirror lacks fails.
* Harness source is only *syntactically* verified in CI; a type error still waits for
  the nightly build job. Stated plainly so nobody reads the replay suite as a fuzzer.
* `--check` ties the corpus to its generator, so editing `examples/fuzz_seeds.rs`
  without regenerating is a failing gate rather than an unnoticed divergence — for the
  deterministic part of the corpus; the AEAD part is checked for presence only, which
  is as far as security allows.
